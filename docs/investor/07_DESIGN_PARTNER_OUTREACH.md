# AICIS Design-Partner Outreach Pack

## Objective

The goal of early outreach is not to sell a finished platform. It is to find an organization with a real resilience/continuity workflow that can be studied and, if appropriate, evaluated through a low-risk historical-replay or shadow-mode pilot.

## Qualification before outreach

A target should satisfy at least three of these conditions:

- monitors multiple operational/public information sources;
- owns resilience, continuity, climate-adaptation or infrastructure workflows;
- experiences alert overload, fragmented evidence or manual triage;
- has a plausible historical dataset or shadow-mode path;
- has an innovation/digitalization mandate;
- can identify a user and a sponsor;
- can run a pilot without depending on AICIS for live safety-critical decisions.

Deprioritize organizations where there is no clear workflow owner, no measurable use case, or no safe evaluation path.

## Core positioning

Use one controlled sentence:

> AICIS is an early-stage evidence-governed resilience intelligence system that helps human decision-makers combine fragmented signals, preserve source provenance, surface uncertainty and review response options through auditable workflows.

Then immediately narrow the ask:

> We are looking for design partners willing to help define and evaluate one concrete workflow through historical replay or shadow mode; we are not asking you to replace an operational system or rely on unvalidated automated decisions.

## Discovery follow-up

After a useful interview, send a one-page recap containing only facts the interviewee actually provided:

1. workflow as understood;
2. current information sources;
3. primary pain points;
4. measurable baseline candidates;
5. data/security constraints;
6. possible historical/shadow evaluation;
7. unresolved questions;
8. proposed next step.

Ask the interviewee to correct the recap. Their correction is valuable evidence.

## Pilot-conversion gate

Do not send a pilot proposal until all of the following are known:

- named workflow;
- operational owner;
- baseline process;
- data boundary;
- evaluation period;
- success and failure metrics;
- human-review role;
- security/privacy constraints;
- person able to approve the pilot.

## Outreach sequence

1. Research organization and likely workflow.
2. Send personalized discovery request.
3. Follow up once after 4–7 business days if appropriate.
4. Conduct discovery using `06_CUSTOMER_DISCOVERY_PLAYBOOK.md`.
5. Score opportunity.
6. Send factual recap for correction.
7. If strong fit, draft a pilot scope using `02_PILOT_BLUEPRINT.md` and `08_PILOT_LOI_TEMPLATE.md`.
8. Record outcomes, including rejection reasons.

## Metrics for the outreach sprint

Track:

- qualified organizations researched;
- personalized messages sent;
- response rate;
- qualified discovery calls;
- strong-fit scores (18+ / 24);
- pilot-scope discussions;
- written design-partner commitments;
- explicit rejection reasons.

The objective is learning and conversion evidence, not inflated activity counts.
